# 디자인 가이드 — Toss-like

- 버전: v0.1 (2026-08-28)
- 대상: 블로그 글쓰기 앱 (갤럭시 탭 S9, 가로/세로 모두)
- 참고: 토스 제품 원칙·UX 원칙, TDS Mobile 컴포넌트 구조, TDS 컬러 시스템 업데이트 글

이 문서는 요구사항 명세가 "별도 문서"로 넘긴 디자인/UX 방향을 정한다. 코드에서는 `ui/theme/` 의 토큰과 `ui/components/` 의 공용 컴포넌트로 구현하며, 화면 코드는 이 토큰과 컴포넌트만 사용한다.

## 1. 원칙 (토스에서 가져온 것 → 이 앱에서의 의미)

| 토스 원칙 | 이 앱에서의 적용 |
|---|---|
| **One Thing per One Page** — 한 화면 한 메시지 | 홈·이력·설정 화면은 큰 제목 한 줄 + 하단 CTA 하나. 글쓰기는 **채팅 한 화면**에서 이루어지되, 대화의 각 턴이 "지금 답할 것 하나"만 묻는다(제목 고르기, 이 계획으로 갈지 등). 초안 작성 단계에서만 오른쪽 사이드 패널이 열린다(§8). |
| **Tap & Scroll** — 누르기와 스크롤만으로 핵심 플로우 완성 | 텍스트 입력은 채팅 입력창 한 곳뿐이고 음성 입력을 기본 제안. LLM 제안에 대한 답은 가능한 한 빠른 답장 칩("이대로 좋아요", "더 짧게", "사진 순서 바꿀래요")으로 탭 한 번에. 드래그·롱프레스는 사진 순서 변경에만 쓰고, 대체 경로(앞/뒤 버튼)를 함께 둔다. |
| **Easy to Answer** — 모든 질문에 3초 안에 답할 수 있게 | 선택지는 최대 3개(제목 후보 2~3개). 질문 문구는 "어떤 제목이 좋으세요?"처럼 대화체 한 문장. |
| **Value First, Cost Later** | 온보딩에서 로그인·설정을 먼저 요구하지 않고, 첫 화면에서 바로 "새 글 쓰기"를 보여준 뒤 필요한 시점에 로그인을 요청한다. |
| **No More Loading** | 기다려야 할 때는 스피너 대신 "사진 올리는 중 2/5" 같은 진행 문장 + 진행 바. 글 생성 중에는 무엇을 하는지 단계별 문장으로 보여준다. |
| **Casual Concept / Less Policy** | "API 키", "세션 만료" 같은 말은 사용자 화면에 쓰지 않는다. "네이버에 다시 로그인해 주세요"처럼 행동으로 말한다. 기술 용어는 관리자 화면에서만. |
| **Sleek Experience** | 화면 전환은 단순 페이드/슬라이드 200ms. 성공 시에는 체크 애니메이션 한 번. 장식 애니메이션 없음. |

추가 원칙 (사용자 특성: 60대, 태블릿):
- **큰 것이 기본**: 본문 17sp 이상, 터치 타겟 최소 56dp, 주요 CTA 높이 60dp.
- **되돌릴 수 있게**: 파괴적 동작(삭제)은 항상 확인 시트. 발행은 사용자가 에디터에서 직접 누른다.
- **막히면 사람에게**: 오류 화면에는 항상 "관리자에게 알리기" 버튼이 있다.

## 4. 스페이싱과 형태

- 스페이싱 스케일: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48dp. 화면 좌우 여백 **24dp** (태블릿), 섹션 간 **32dp**, 리스트 행 내부 **16dp**.
- 라운드: 버튼·입력 필드 **16dp**, 카드 **20dp**, 바텀시트 상단 **24dp**, 썸네일 **12dp**, 칩 **999dp**.
- 그림자: 쓰지 않는다. 카드는 배경색 차이(`surface` on `backgroundAlt`) 또는 1dp `border`로 구분.
- 아이콘: Material Symbols Rounded, 24dp(리스트) / 28dp(버튼 내).

## 6. 문구 (카피) 규칙

- 존댓말 "~해요"체. 명령문 대신 제안문: "사진을 골라 주세요" → "어떤 사진으로 쓸까요?"
- 버튼은 동사로 끝: "다음", "이 제목으로", "발행하러 가기", "다시 시도".
- 오류 문장 구조: [무슨 일] + [어떻게 하면 되는지]. 예: "네이버 로그인이 풀렸어요. 다시 로그인하면 쓰던 글을 이어서 올릴게요."
- 숫자는 아라비아 숫자, 단위 붙여쓰기: "사진 5장", "2분 전".
- 기술 용어(API, 세션, 토큰, HTML, WebView)는 사용자 화면 금지.

## 7. 화면 구조 규칙

- 사용자 화면 계층: **글쓰기 채팅(시작 화면) → 초안**. 깊이 2를 넘지 않는다. (2026-08-29 결정: 홈과 발행 기록 화면은 없앴다.)
- 관리자 화면은 왼쪽 대화 기록 사이드바 맨 아래 톱니 아이콘 → 설정. 사용자 화면과 같은 토큰을 쓰되 기술 용어 허용, 밀도 높은 리스트 허용.
- 뒤로가기: 입력이 있는 화면에서는 자동 저장하므로 확인 없이 나간다 (FR-4.4, FR-6.4).
- 가로/세로 모두 지원. 설정·초안 등 단일 목적 화면은 **단일 컬럼을 720dp 폭으로 가운데 정렬**. 글쓰기 채팅 화면만 §8 의 2단 배치를 쓴다.

## 8. 글쓰기 화면 = 채팅 + 사이드 패널 (2026-08-28 결정)

사용자는 ChatGPT 류 채팅에 익숙하므로 글쓰기는 채팅으로 진행하고, "초안 작성"을 요청한 시점에만 오른쪽에 네이버 에디터(WebView) 패널이 열린다.

**시작 화면 (2026-08-29 결정)**
- 앱을 켜면 바로 이 채팅이다. 아직 메시지가 하나도 없는 "새 글"은 목록 대신 화면 가운데에 `display` 제목("오늘은 어떤 이야기를 올릴까요?")과 그 아래 큰 입력창(가로 최대 720dp, 높이 132dp, 사진·마이크·보내기 버튼 포함)만 보여 준다. 사진판은 그 입력창 바로 위.
- 첫 메시지(또는 첫 사진)를 보내는 순간 대화가 만들어지고 보통 채팅 배치(하단 입력창)로 바뀐다 — 빈 대화는 목록에 쌓이지 않는다.
- 왼쪽 사이드바 맨 아래에는 늘 설정 톱니가 있다(펼친 목록·72dp 레일·세로 드로어 모두).

**흐름**
1. 사용자가 사진을 고르고(첨부 버튼 → PhotoGrid 메시지) 아이디어를 말하거나 적는다.
2. 어시스턴트가 **계획 카드**로 답한다: "이렇게 써 볼까요?" + 제목 후보 2~3개 + 문단 구성 요약(사진 배치 포함). 카드 아래에 빠른 답장 칩: "이대로 좋아요", "제목만 바꿀래요", "더 짧게", "다른 이야기도 넣을래요".
3. 2~3턴 다듬기. 어시스턴트는 매 턴 질문을 하나만 한다.
4. 사용자가 "초안 작성해 줘"(칩 또는 자유 입력)라고 하면 오른쪽 패널이 열리고 `PublishPanel`(진행 → 에디터 → 결과)이 표시된다. 채팅은 그대로 왼쪽에 남아 "문단 2를 더 짧게" 같은 부분 수정 요청을 계속 받을 수 있다(수정 시 패널의 에디터에 재주입).
5. 사용자가 패널 안 에디터의 "발행"을 직접 누른다. 발행이 감지되면 채팅에 "발행했어요 🎉" 시스템 메시지 + 링크.

**배치**
- 가로(기본): 왼쪽 채팅(나머지 폭), 오른쪽 패널 **폭 = 화면의 50%, 최소 520dp**. 패널은 오른쪽에서 슬라이드 인(200ms). 패널 상단에 얇은 바: 상태 문장("사진 올리는 중 2/5") + "패널 접기"(접으면 채팅이 전체 폭, 상단 InlineBanner로 상태 유지).
- 세로: 패널이 채팅 위를 덮는 전체 화면 시트로 열리고, 상단 왼쪽 "채팅으로" 버튼으로 돌아간다. 상태는 시트 안에서 동일하게 표시.
- 채팅 입력창은 하단 고정: 왼쪽 첨부(사진), 가운데 텍스트, 오른쪽 마이크(길게 누르지 않고 탭으로 시작/정지) + 보내기. 높이 60dp, `surfaceWeak` 배경, 라운드 24dp.

**메시지 스타일**
- 사용자 말풍선: 오른쪽, `fillBrand` 배경 + `textOnBrand`, 라운드 20dp(오른쪽 아래 6dp).
- 어시스턴트 말풍선: 왼쪽, `surfaceWeak` 배경 + `textPrimary`, 라운드 20dp(왼쪽 아래 6dp). 아바타 없음.
- 계획 카드: 어시스턴트 쪽에 `surface` + 1dp `border` 카드. 제목 후보는 라디오처럼 선택 가능한 ListRow 3개.
- 시스템 메시지(발행 완료, 로그인 필요): 가운데 정렬 InlineBanner.
- 본문 글자 `body1`(17sp). 말풍선 최대 폭은 채팅 영역의 80%.
- 어시스턴트가 생각 중일 때: 말풍선 안 점 세 개 애니메이션 + "글을 구상하고 있어요" `caption`.
